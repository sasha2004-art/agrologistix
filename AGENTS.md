# Правила работы агента

## Обязательное чтение документации

* Перед началом любой задачи (и при каждом возврате к работе над проектом) полностью прочитывай документацию и следуй ей:
  * `docs/planning/01-prd.md` … `docs/planning/08-roadmap-14-days.md` — требования, архитектура, дизайн, задачи и 14-дневный roadmap;
  * `docs/LAUNCH.md` — запуск и развёртывание (файл генерируется из `docs/launch.config.json`, вручную не редактируется);
  * этот файл `AGENTS.md`.
* Соблюдай `docs/planning/07-coding-convention.md`: лимит **500 строк** на кодовый файл, запрет Tailwind CSS, вертикальные срезы на фронтенде и слоистую архитектуру на бэкенде.
* Если задача описана в `docs/planning/08-roadmap-14-days.md`, выполняй именно её объём для соответствующего дня и роли (Dev 1 — Backend/Math/DevOps, Dev 2 — Frontend/UI/Map).
* При изменении контрактов API или конфигурации запуска обновляй соответствующие документы/схемы и фиксируй это в ответе.

## Инструменты

* В системе установлен GitHub CLI `gh`; его можно использовать для работы с GitHub от имени пользователя.

## Git-гигиена

* Основная ветка — `main`, изменения вливаются через pull request.
* **Всегда удаляй ветку после слияния её PR**: и локальную, и удалённую. Предпочтительно `gh pr merge <n> --merge --delete-branch`; иначе явно `git push origin --delete <branch>` и `git branch -d <branch>`.
* Не оставляй слитые ветки ни локально, ни на remote.
